# Типографика и палитра

Общие токены находятся в `core/theme/createAppTheme.ts`, шкала — в
`core/theme/typography.ts`. Превью компонентов доступно на `/themes`.

## Размеры

Базовый размер браузера не уменьшаем. Размеры текста задаём в `rem`.
Минимальный читаемый текст интерфейса — 1rem (16 CSS px при стандартной
настройке браузера). Иконки и декоративная графика не относятся к этому ограничению.

| Роль                    | Телефон | Компьютер | Вес |
| ----------------------- | ------- | --------- | --- |
| h1                      | 32/40   | 48/58     | 700 |
| h2                      | 26/34   | 32/42     | 700 |
| h3 / заголовок формы    | 22/30   | 24/32     | 700 |
| body1 / статья          | 18/30   | 18/30     | 400 |
| subtitle1               | 18/27   | 18/27     | 600 |
| body2, caption, подписи | 16/24   | 16/24     | 400 |
| subtitle2 / навигация   | 16/24   | 16/24     | 600 |
| Кнопка                  | 16/24   | 16/24     | 700 |
| Ввод                    | 18/26   | 18/26     | 400 |

Смысловой HTML-тег выбираем через `component` по структуре документа.
Длинные названия и подписи переносятся, высота зависит от содержимого.
Колонка статьи ограничена примерно 65ch; мобильные внешние поля — 16px.
Основной текст статьи 18/30 сохраняется на телефоне.

## Контролы и состояния

Кнопки — минимум 48px; IconButton — минимум 44px. Высота полей определяется
размером MUI (`small`, `medium`), отступами и содержимым; глобальная минимальная
высота не задана. Описание публичной заявки — минимум 144px. Бейджи и Chip
имеют автоматическую высоту, допускают несколько строк.

Подписи полей находятся в потоке над полем, остаются 16px при вводе и
переносятся целиком. Плавающее уменьшение scale(0.75) не используется.
У outlined-поля legend скрыт: подпись не разрывает границу поля.
`MuiDialogContent` сохраняет верхний отступ 16px после заголовка диалога,
чтобы плавающие подписи не обрезались. Длинные формы прокручиваются.

Фокус виден при навигации клавиатурой: контур 2px и отступ с контрастной
подложкой. У полей MUI фокус обозначает собственная рамка или подчёркивание;
дополнительный контур вокруг поля и его внутреннего input не добавляется.
Ошибки сопровождаются текстом. Поля и auth-карточки используют
непрозрачные поверхности, чтобы контраст не зависел от фотографии под ними.

## Компоновка

Каталог услуг до 600px показывает одну карточку в строке. Помощь с выбором
услуги находится в потоке страницы и не закрывает карточки. Мобильный диалог
заявки остаётся на всю ширину.

Клиентские заявки до 900px отображаются вертикальными группами статусов.
На компьютере колонки не сжимаются меньше 320px и могут прокручиваться
внутри доски. Нижняя навигация кабинета резервирует 88px плюс safe area.

## Проверки

- `npm run typography:check`: проверяет явные числовые размеры текста в TS/TSX/CSS;
  иконки исключены. Проверка не заменяет измерение наследуемых размеров в браузере.
- `npm run test -- core/theme/createAppTheme.spec.ts`: размеры текста и
  исходные цвета палитры.
- Полный `npm run test`, TypeScript, ESLint и production build.
- В браузере: 320, 390, 768, 1024, 1440, 1920px, заполненные поля,
  клавиатурный фокус, 200% увеличение и пользовательские текстовые интервалы.

Минимум 16px — правило проекта для читаемости. Исходная палитра не проходит
автоматически проверку контраста WCAG для всех сочетаний цветов.

## Сохранённые страницы авторизации

По отдельному требованию `/signin` и `/signup` сохраняют прежние размеры,
палитру, плавающие подписи и оформление на тёмном стекле. Их page.tsx
восстановлены без изменений. `AppProviders` выбирает для этих двух маршрутов
`legacyAuthTheme.ts`, а `RainGlassPaper` — исходный `LegacyAuthPaper`.
Остальные маршруты используют общую тему. Эти четыре файла
явно исключены из проверки минимального размера текста.

Цвет предупреждений в светлой теме снова берётся из `lime[900]`. При смене режима ThemeProvider
перерисовывает зависимые от темы стили через `forceThemeRerender`.
