# Будущая возможность: «Подписать КЭП»

Статус: запланировано на будущее, реализация не начата.

Решение от 02.11.2026: сейчас договор обязателен, прикрепление готового файла подписи опционально. Отдельная возможность **«Подписать КЭП» для пользователей с настроенным рабочим местом** будет добавлена позднее.

## Текущий сценарий

- Исполнитель загружает файл договора в PDF или DOCX.
- Готовую отсоединённую подпись `.sig`, `.sgn` или `.p7s` можно приложить при наличии. Кнопка «Прикрепить файл подписи» только загружает уже созданный файл.
- Отсутствие подписи не блокирует загрузку, одобрение и акцепт договора. Требования к согласованной цене, одобрению всех пакетов и загрузке запрошенных документов сохраняются.
- Сайт не заявляет, что приложенная подпись криптографически проверена.

## Будущий сценарий

1. Пользователь открывает окончательную версию договора и выбирает «Подписать КЭП».
2. Сайт проверяет готовность рабочего места, наличие поддерживаемого ПО и доступных сертификатов.
3. Пользователь выбирает сертификат и подтверждает операцию в криптографическом ПО.
4. Созданная отсоединённая подпись автоматически прикрепляется к конкретной версии договора.
5. Сервер проверяет соответствие подписи точным байтам документа, сертификат и связь подписанта со стороной сделки. Только подтверждённый результат проверки допускает статус «Подпись проверена».

Первый кандидат для технического прототипа: КриптоПро CSP + ЭЦП Browser plug-in + расширение браузера; интеграция фронтенда через официальный `cadesplugin_api.js`. Альтернатива для поддерживаемых устройств — JavaScript API Рутокен Плагина.

Закрытый ключ не передаётся на сервер. Изменение файла договора требует новой подписи. Не настроенное рабочее место не должно блокировать основной сценарий загрузки договора и опционального прикрепления готовой подписи.

До реализации уточнить поддерживаемые ОС, браузеры и токены, лицензирование ПО, способ серверной проверки и сохранение доказательств проверки. Не добавлять неработающую кнопку подписания в текущий интерфейс.
