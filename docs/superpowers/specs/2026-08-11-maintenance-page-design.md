# Страница технических работ — Design

Дата: 2026-08-11  
Статус: approved

## Цель

При недоступности бэкенда/БД или плановых работах показывать спокойный брендированный экран вместо Next.js Runtime Error, чтобы пользователь не пугался технических деталей.

## Решения (согласовано)

| Вопрос | Решение |
|--------|---------|
| Охват | Весь фронт: публичка, кабинеты, admin |
| UI | Отдельный спокойный экран: логотип + текст + «Обновить», без SiteChrome |
| Аварийный путь | `app/error.tsx` + `app/global-error.tsx` |
| Плановый путь | `MAINTENANCE_MODE=true` → middleware → `/maintenance` |
| Вход / кабинет при outage | Войти нельзя — это нормально. На `/signin` **нельзя** маскировать outage под «неверный email или пароль»; нужно сообщение о технических работах |
| 5xx vs 404 | 5xx не маскировать под `notFound()` |

## Архитектура

Два независимых триггера:

1. **Авария** — необработанный backend 5xx / сетевой сбой при SSR → error boundary → `MaintenanceScreen`.
2. **План** — env `MAINTENANCE_MODE=true` → middleware rewrite/redirect на статический `/maintenance` без вызовов бэка.

Корневой `app/error.tsx` лежит вне `(site)` layout, чтобы не рендерить Header/Footer/CabinetChrome.

Детекция outage на клиенте — по `error.message` (кастомные поля `BackendApiError` не сериализуются через RSC → client boundary).

## UI

Компонент `MaintenanceScreen`:

- логотип `/zemledel_logo_light.svg`
- заголовок: «Ведутся технические работы»
- текст: сервис временно недоступен, можно зайти позже
- кнопка «Обновить страницу»
- токены бренда: primary `#006E4D`, bg `#F4F7F6`

Для прочих (не-outage) ошибок — мягкий generic: «Что-то пошло не так» + «Обновить», без стека.

## Follow-up (план работ)

- **`/signin` при outage:** сейчас форма всегда показывает «Неверный email или пароль», если `signIn("credentials")` вернул `error`. Нужно отличать отказ БД/бэкенда (5xx, сеть) от неверных учётных данных и показывать экран/текст технических работ.
- Восстановление пароля — отдельный пункт roadmap в `docs/business-logic.md`, не часть этого экрана.

## Вне скоупа

- Healthcheck бэка без ошибки запроса
- Отдельный статус-пейдж / ETA
- Изменения бэкенда (кроме различения outage vs invalid credentials на пути login)
