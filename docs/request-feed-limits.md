# Ограничения ленты заявок

`GET /pro/requests/feed` защищён штатным `@nestjs/throttler` через
`RequestFeedThrottlerGuard`. На одного авторизованного пользователя действуют
оба ограничения: 30 запросов за 10 секунд и 120 за минуту. Параметры находятся
в `backend/src/requests/request-feed-throttler.guard.ts`.

Бюджет общий для всех услуг, свободных заявок, поиска и страниц пагинации.
Смена query-параметров, IP или клиентских заголовков его не обнуляет.
Идентификатор берётся только из проверенного `x-internal-auth`, который Next.js
подписывает после проверки сессии. IP Next.js общий для посетителей, поэтому
он не используется как ключ. Неподписанный идентификатор и `X-Forwarded-For`
не считаются подтверждением пользователя.

Guard выполняется до проверки организации и выборки заявок из БД. При
превышении лимита возвращает `429 Too Many Requests` и стандартный `Retry-After`
в секундах. Next.js передаёт их браузеру, интерфейс показывает время ожидания.
При превышении короткого лимита ожидание составляет 10 секунд с момента
блокировки, минутного — 60 секунд. Повторные запросы во время блокировки не
продлевают её. Если превышены оба лимита, `Retry-After` содержит большее время.

Интерфейс показывает предупреждение с обратным отсчётом, сохраняет загруженные
заявки и отключает «Ещё»/«Повторить»/«Показать новые» до окончания ожидания.
Ожидание общее для услуг, поиска и вкладки свободных заявок. В течение этого
времени клиент не отправляет новые запросы ленты, включая фоновые обновления.
После окончания ожидания загрузку можно повторить вручную.
Автоматических повторов после `429` нет. Запрос без внутренней авторизации
отклоняется до обращения к БД.

Ограничение размера страницы действует независимо: по умолчанию 3 заявки,
максимум 5; недопустимый размер возвращает `400`. «Ещё» запрашивает следующие 5.
Завершённые, закрытые и отменённые заявки исключаются в БД.

Используется встроенное хранилище счётчиков в памяти одного процесса backend
(в `deploy/docker-compose.prod.yml` один экземпляр). Перезапуск сбрасывает
счётчики. Перед запуском нескольких процессов или реплик нужно подключить
общее хранилище через интерфейс `ThrottlerStorage`, например Redis.

Это ограничение обращений к ленте, а не защита всей инфраструктуры от DDoS.
Ограничение входящего трафика по IP на внешнем прокси/хостинге настраивается
отдельно; этот код его не включает и не меняет настройки доверенных прокси.
