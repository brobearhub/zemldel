# Переход на zemledel.ru

Все команды ниже выполняются из корня проекта. База, сеть, S3-бакеты, ключи
доступа и сами приложения остаются прежними. Миграции БД, восстановление городов
и сиды из-за смены домена не нужны. Перенос старых картинок и редиректы со старого
домена не требуются: проект ещё на старте.

## 1. Проверить Terraform

В `infra/terraform/terraform.tfvars` уже установлен `domain = "zemledel.ru"`.
`enable_cdn_tls` пока остаётся `false`: выпуск сертификата запускается после DNS.

Домен уже существует в DNS-хостинге. 5 ноября 2026 года он импортирован в локальный
state; перед импортом создана закрытая резервная копия `terraform.tfstate.before-domain-*`.
Повторно импортировать его в этом рабочем каталоге не нужно. Для другого state,
если этот же домен ещё не отслеживается, команда импорта:

```sh
terraform -chdir=infra/terraform import \
  'restapi_object.domain["zemledel.ru"]' \
  '/api/v1/domains/zemledel.ru'
```

Посмотреть план:

```sh
terraform -chdir=infra/terraform plan
```

Ожидаются новая CNAME-запись CDN, настройка домена раздачи существующего CDN,
удаление старой DNS-привязки и старой CNAME-записи. Удаление DNS-привязки означает
удаление старого домена из панели DNS-хостинга и может затронуть его почту;
это не отмена регистрации домена у регистратора. База, S3 и сеть не должны
удаляться или пересоздаваться; CDN также должен сохранить ID.

После проверки плана применить его:

```sh
terraform -chdir=infra/terraform apply
```

CDN не создаётся второй раз: скрипт `ensure-cdn-domains.py` через PATCH меняет
список алиасов существующего ресурса на технический hostname и `cdn.zemledel.ru`.
Старые пользовательские алиасы удаляются. Это действие выполняется только при apply.
Документация API: [домены CDN](https://timeweb.cloud/docs/cdn/settings/origin-and-domains),
[PATCH configuration](https://github.com/timeweb-cloud/sdk-go/blob/main/docs/UpdateHttpResource.md).

## 2. Привязать домены к существующим приложениям

- Frontend: `zemledel.ru`; при необходимости также `www.zemledel.ru`.
- Backend: `api.zemledel.ru`.
- CDN: `cdn.zemledel.ru` — CNAME управляется Terraform.

Привязки frontend/backend выполняются в настройках доменов соответствующих
приложений AppPlatform. Новые приложения создавать не нужно. Платформа выпускает
сертификат после подключения домена: [описание SSL](https://timeweb.cloud/docs/apps/ssl-certificates).

Если панель создаёт A/CNAME автоматически, не добавляйте дубли через `dns_records`.
Либо оставьте эти записи под управлением панели, либо сначала импортируйте их
в Terraform. Для почты также используйте реальные записи выбранного почтового сервиса.

Проверка DNS:

```sh
dig +short NS zemledel.ru
dig +short A zemledel.ru
dig +short A api.zemledel.ru
dig +short CNAME cdn.zemledel.ru
terraform -chdir=infra/terraform output -raw cdn_cname_target
```

NS уже делегированы в текущий DNS-хостинг. При проверке 5 ноября корневой домен
отвечал `201.24.117.24`; подтвердите в панели, что это именно адрес frontend.
`api` и `cdn` тогда ещё не возвращали указанные записи. DNS может измениться;
повторите команды перед переключением.

## 3. Выпустить сертификат CDN

Когда CNAME совпадёт с `cdn_cname_target`, установите в `terraform.tfvars`:

```hcl
enable_cdn_tls = true
```

Затем:

```sh
terraform -chdir=infra/terraform plan
terraform -chdir=infra/terraform apply
```

Terraform запросит и дождётся сертификата для нового CDN-домена. До готовности
HTTPS не переключайте `CDN_PUBLIC_BASE_URL` работающего backend.

## 4. Обновить переменные и пересобрать приложения

Backend в панели приложения:

```dotenv
FRONTEND_URL=https://zemledel.ru
CDN_PUBLIC_BASE_URL=https://cdn.zemledel.ru
MESSENGER_SITE_URL=https://zemledel.ru
MESSENGER_WEBHOOK_BASE_URL=https://api.zemledel.ru
```

Frontend:

```dotenv
NEXTAUTH_URL=https://zemledel.ru
NEXT_PUBLIC_CHAT_SOCKET_URL=https://api.zemledel.ru
```

Если `BACKEND_API_URL` использует публичный адрес, замените его на
`https://api.zemledel.ru`. Если используется действующий приватный адрес backend,
оставьте его: смена внешнего домена приватную сеть не меняет.

`DATABASE_URL`, S3 endpoint/bucket/key/secret, `DOCUMENTS_MASTER_KEY_BASE64`,
`NEXTAUTH_SECRET`, `INTERNAL_API_SECRET` и `SOCKET_JWT_SECRET` менять не требуется.
Для `NEXT_PUBLIC_*` нужна новая сборка frontend, одного рестарта недостаточно.
Backend тоже пересоберите, чтобы опубликовать документы с новым адресом.
Cookies со старого домена не перенесутся: потребуется повторный вход.

Локальный `backend/.env` обновлён только в адресах мессенджеров. Это не меняет
переменные в панели приложений и не переключает почтового отправителя.

## 5. Почта и интеграции

1. Если нужна почта `support@zemledel.ru`, создайте новый ящик или алиас у почтового
   провайдера. Ящик старого домена автоматически не переименовывается.
2. Добавьте выданные сервисом MX, SPF, DKIM и DMARC для нового домена. Не копируйте
   DKIM старого домена и не создавайте несколько SPF-записей для одного имени.
3. Для отправки через Postbox подтвердите новый домен, дождитесь успешной DKIM-проверки
   и только затем измените `SMTP_FROM` на новый адрес. Ключи сервиса обычно остаются
   прежними при сохранении аккаунта/прав. [Настройка отправителя](https://yandex.cloud/ru/docs/postbox/quickstart).
4. Проверьте webhooks Telegram/MAX: после смены публичного API старый URL останется
   зарегистрирован у сервиса. В консоли backend выполните `npm run messengers:check`.
   `messengers:setup` намеренно отказывается заменять чужой URL: подтверждённый старый
   webhook нужно переключить отдельно с сохранением очереди, затем повторить настройку.
   См. [мессенджеры](messengers.md). Секреты и токены ботов из-за домена не меняются.
5. Если подключены внешние OAuth-провайдеры, аналитика или поисковые кабинеты,
   обновите там callback/разрешённый домен/адрес сайта.

## 6. Проверить после деплоя

- Открываются `https://zemledel.ru` и `https://api.zemledel.ru` с валидным TLS.
- Работают вход, выход, регистрация и сброс пароля; письмо ведёт на новый сайт.
- Работают чат, загрузка новой картинки и её открытие через CDN.
- Приватные документы остаются закрыты без авторизации.
- Проверены получение сообщения ботом и ссылка из бота на сайт.
- `robots.txt`, `sitemap.xml`, `llms.txt`, Open Graph и текущие юридические документы
  используют новый домен. Юридическим документам присвоена новая редакция 2026-11-05;
  прежняя редакция сохранена только в архиве исходников.

Подготовка конфигурации и импорт state не переключают работающие приложения.
Применение инфраструктуры, выпуск нового CDN-сертификата, обновление переменных
в панели и production-деплой выполняются отдельно.
