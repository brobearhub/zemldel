# Раздел «Участки»

## Экраны и сценарии

- `/lands` по умолчанию показывает предложения о продаже плиткой на экранах уже 900 px и списком на более широких. На мобильном доступны плитка и карта. `?view=tiles` открывает плитку, `?view=map` — карту. Старые ссылки с `?map=1` также открывают карту. Услуги подбора доступны по `?kind=SELECTION`, личное избранное — по `?favorites=1`. Фильтры, сортировка, страница и область карты сохраняются в URL.
- `/lands/[id]` — предложение, цена и условия конкретного вида сделки, сведения автора, фотографии, расположение, контакты. Переход из каталога сохраняет ссылку возврата с фильтрами.
- `/lands/new` и `/lands/[id]/edit` — форма с тематическими карточками. У продажи отдельно заполняются паспорт, расположение, цена, характеристики, публичное объявление и документы с контактами. У подбора есть география, состав работы и условия оплаты. Черновик можно сохранить без заполнения обязательных для публикации полей. Выбор проверки документов сохраняется с черновиком и передаётся на модерацию при отправке.
- `/lands/mine` — личные объявления и объявления организаций, которыми пользователь вправе управлять; статусы, редактирование, отзыв с модерации, снятие с публикации, удаление неопубликованного черновика.
- `/admin/lands` — модерация содержания и отдельная добровольная проверка документов. Решение по документам содержит предмет/результат проверки и дату.

Продажа доступна клиенту и исполнителю. Подбор публикуется от организации исполнителя. Виды продажи: участок целиком, доля в праве и уступка права аренды. Выбранные автором цели использования не являются заключением о возможности строительства.

## Связи данных

| Сущность | Связи и правило |
| --- | --- |
| `LandParcel` | Уникальный кадастровый номер; один участок может иметь несколько предложений. Площадь, координаты, ВРИ и другие заявления автора хранятся в объявлении, а не перезаписывают общий объект. |
| `LandListing` | Автор `User`, необязательный `Provider`, кадастровый объект и необязательная ссылка на `City` для продажи. Подбор связан с отдельным уникальным `Service`. Тип предложения и профиль публикации сохраняются после создания. |
| `LandListingRevision` | Рабочая версия опубликованного объявления. Хранит редактируемые данные, порядок прикреплённых файлов, статус изменений и результат проверки документов этой версии. |
| `LandMedia` | Файл принадлежит одному объявлению; фотографии и документы имеют разные правила выдачи. Удаление файла проходит через очередь `LandObjectCleanup`. |
| `LandFavorite` | Уникальная пара пользователь/объявление. Не использует избранное услуг и не создаёт лид исполнителю. |
| `LandReview` | Решение модератора, вид проверки, причина и версия объявления. Проверка содержания не подтверждает документы или право собственности. |
| `Service` | Для подбора синхронизируется с объявлением в той же транзакции: статус, описание, цена, география, фотографии. Управление через обычные методы редактирования/удаления услуги запрещено; редактор направляет в «Участки». |
| `Request` | Заявка на подбор создаётся существующим процессом услуги, со стандартным чатом и дальнейшим жизненным циклом. Перед созданием блокируется объявление и повторно проверяется публикация, чтобы снятие и создание заявки не расходились. |
| `Conversation` | Для продажи добавлен вид `LAND`: объявление + покупатель, продавец — организация либо физическое лицо. Повторный контакт открывает ту же переписку. Для других видов сохранены прежние ограничения обязательных связей. |

Чаты используют существующие сообщения, WebSocket, индикаторы непрочитанного, присутствие и маршруты `/profile/chats/direct/[id]` / `/pro/chats/direct/[id]`. В переписке есть переход к объявлению. Земельная переписка не создаёт заявку на услугу и не запускает оплату участка.

Цена подбора с единицей расчёта (например, `10000 ₽ / подбор`) передаётся в услугу как условие предложения. Она не становится автоматически окончательной суммой договора; стоимость заявки согласуется существующим процессом.

## Доступ и жизненный цикл

Личное объявление редактирует автор. Объявление организации — её действующий `OWNER` или `MANAGER`. После исключения из организации первоначальный автор теряет доступ. `EMPLOYEE` не управляет объявлениями организации, но сохраняет свои личные объявления и земельные переписки. Администратор модерирует, а не публикует от чужого имени.

При первой публикации объявление проходит `DRAFT → PENDING → PUBLISHED`. Если модератор возвращает объявление, автор видит статус `CHANGES_REQUIRED` и замечание. Во время модерации автор может отозвать материал в черновик.

При редактировании опубликованного объявления создаётся рабочая версия. Автор и модератор видят её в карточке, в каталоге и по обычной ссылке посетители видят последние одобренные условия и фотографии. В «Моих объявлениях» запись можно найти и по статусу «Опубликовано», и по стадии правок. Фильтры каталога, карта, избранное и связанная услуга подбора продолжают использовать опубликованные данные. Авторам и модераторам доступна ссылка `/lands/[id]?published=1` на опубликованную версию.

Сохранение, отправка правок, возврат на доработку и отзыв в черновик сохраняют публикацию. Одобрение содержания обновляет объявление по тому же адресу. Отдельное решение по документам относится к проверяемой версии. При явном снятии с публикации объявление переходит в `WITHDRAWN`, последние правки сохраняются. Для повторной публикации требуется одобрение модератора.

Запись сериализуется блокировкой строки и проверкой версии: конфликт возвращает 409 вместо потери изменений. При существующей переписке нельзя заменить кадастровый номер или вид сделки. Опубликованное ранее объявление не удаляется физически. Удаление допускается только для черновика без истории публикации, переписки и заявок; связанные файлы очищаются повторяемыми фоновыми задачами.

После снятия предложения существующие переписки и заявки сохраняются. Публичная карточка показывает недоступность без раскрытия изменяемых данных; новый контакт не создаётся. Черновики недоступны посторонним. В каталоге, карте и sitemap присутствует только `PUBLISHED`.

## Семантика полей

- Площадь хранится в м²; интерфейс поддерживает м², сотки и гектары. Для доли всегда показываются размер доли, цена доли и площадь **всего** кадастрового участка. Площадь «выделенной доли» и цена её сотки не рассчитываются.
- Для уступки отдельно хранятся цена уступки, арендная плата и период, срок/бессрочность, арендодатель, условия согласия, дополнительные платежи и сведения о задолженности.
- Категория земли, ВРИ, предполагаемые цели, границы, ограничения, коммуникации, подъезд и постройки — независимые поля. «Неизвестно» не заменяется на «Нет».
- Поле «ВРИ по документам» открывает дерево с поиском по коду, названию и сокращению. Каждая отметка соответствует одному ВРИ из документов, включая общие коды. Вложенность кодов служит для навигации. Свои формулировки можно добавить на вкладке «Свой ВРИ». Кнопка «Применить» переносит выбор в форму. В `permittedUses` сохраняются официальные названия и введённый автором текст. Справочник в `frontend/entities/land/permitted-uses.json` воспроизводит коды и наименования из приложения к приказу Росреестра № П/0412, в редакции, действующей с 15 сентября 2026 года. [Текст классификатора](https://base.garant.ru/75062082/53f89421bbdaf741eb2d1ecc4ddb4c33/) · [Приказ о внесении изменений № П/0278/26](https://www.roscadastre.ru/html/docs/2026/0001202609040013.pdf)
- Кадастровый номер обязателен при публикации продажи. Координаты указывает автор; автоматической проверки ЕГРН, кадастровых контуров или разрешённости строительства нет. Карточка содержит переход в НСПД и поясняет происхождение данных.

## Карта и файлы

При выборе города в форме продажи карта показывает оранжевую метку в его центре. Если координаты ещё пусты, форма подставляет широту и долготу центра. Если автор уже отметил участок, выбор города показывает центр для ориентира. Кнопка «К точке участка» возвращает карту к указанным координатам. При открытии сохранённого объявления карта показывает точку участка.

Для центра города сервер использует выбранную запись ГАР. Если в справочнике представлен городской округ, адаптер может найти город по названию и региону. При выборе адресной подсказки форма показывает точность и подставляет координаты. Автор может уточнить их кликом на карте или вводом широты и долготы.

В «Паспорте участка» зелёная галочка или Enter запускают поиск по полному кадастровому номеру. При одном совпадении форма заполняет адрес, доступные координаты и населённый пункт из местного справочника. Для квартиры ориентиром служит адрес дома. При нескольких совпадениях или отсутствии адреса доступен ручной ввод. Кнопка «Сохранить черновик» сохраняет результат.

### Настройка геокодирования

Backend выбирает адаптеры при запуске. В `backend/.env` или переменных окружения сервера задайте `GEOCODING_PROVIDER=dadata`. Это также значение по умолчанию. Для отдельных операций предусмотрены переопределения.

| Переменная | Операция |
| --- | --- |
| `GEOCODING_SUGGESTIONS_PROVIDER` | Поиск адресных подсказок и получение координат выбранного адреса |
| `GEOCODING_CITY_CENTER_PROVIDER` | Центр населённого пункта |
| `GEOCODING_CADASTRAL_PROVIDER` | Поиск объекта по кадастровому номеру |

Пустое значение наследует общий выбор. Сейчас зарегистрирован `dadata`. Его параметры — `DADATA_API_KEY`, `DADATA_SUGGESTIONS_URL` и необязательный `DADATA_FIND_ADDRESS_URL`. По умолчанию URL поиска по номеру выводится из URL подсказок. После изменения выбора перезапустите backend. [Пример настроек](../backend/.env.example)

Чтобы добавить поставщика, реализуйте нужные интерфейсы из `geocoding.ports.ts` и зарегистрируйте фабрику под его именем в `geocoding.module.ts`. При неизвестном имени или отсутствии выбранной операции backend завершает запуск с указанием проблемной настройки. [Контракты](../backend/src/geocoding/geocoding.ports.ts) · [Регистрация адаптеров](../backend/src/geocoding/geocoding.module.ts)

Страницы используют клиент `frontend/entities/geocoding/api.ts`. Он обращается к четырём операциям авторизованного API под `/api/geocoding` — `address-suggestions`, `resolve-address`, `city-center` и `cadastral-location`. Подсказка содержит ссылку на выбранный адрес (`reference`), которую клиент передаёт для уточнения целиком. Точка содержит широту, долготу, точность и источник для атрибуции. Прежние маршруты геокодирования `/api/lands/*` поддерживают прежние форматы ответов. [Клиент геокодирования](../frontend/entities/geocoding/api.ts)

### Карта каталога

Кнопка «Найти» применяет фильтры для всех трёх видов. Город выбирается из справочника по `cityId`. API принимает полные кадастровые номера через запятую в `cadastralNumbers` и находит любой из них. С выбранным городом, диапазонами и другими условиями этот фильтр действует совместно. Несколько назначений в `purpose` также объединяются по правилу «любое из выбранных».

Карта использует react-map-gl с MapLibre GL JS. Движок загружается на клиенте и требует WebGL. При перемещении поиск обновляется кнопкой «Искать в этой области». Сервер ограничивает карту 500 предложениями и сообщает об ограничении. Для более точного поиска можно уменьшить область или добавить фильтры. Предложения одного кадастрового объекта объединены в маркер. При расхождении координат разных авторов маркер использует координаты одного из найденных предложений.

Подложка по умолчанию — OpenStreetMap с атрибуцией. Поставщик настраивается при сборке frontend. Для своего источника нужны растровые тайлы 256 × 256 и разрешение CORS для домена приложения.

```dotenv
NEXT_PUBLIC_LAND_MAP_TILE_URL=https://tile.openstreetmap.org/{z}/{x}/{y}.png
NEXT_PUBLIC_LAND_MAP_ATTRIBUTION=&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a>
```

Все файлы записываются существующим `DocumentStorageService` в приватное хранилище с KMS, префикс `documents/lands/`. Настройка — [приватное хранилище документов](private-document-storage.md). При каждом запросе к API проверяется, что фотография входит в опубликованную версию. Снимок, заменённый в черновике, остаётся виден покупателям до одобрения изменений или снятия объявления. Документы выдаются только владельцу/управляющему и администратору, как вложения с `private, no-store` и `nosniff`; загрузка не означает подтверждение.

К объявлению можно добавить до 6 фотографий размером до 10 МиБ каждая и до 10 документов размером до 15 МиБ каждый. Изображения JPEG/PNG/WebP декодируются, ограничиваются 40 млн пикселей, поворачиваются, уменьшаются до 2400 px и перекодируются в WebP без EXIF. Документы также принимают PDF с проверкой сигнатуры. Незавершённые загрузки и удалённые файлы очищаются через `LandObjectCleanup`; ошибка хранилища оставляет задачу для повтора.

## Запуск и проверки

Перед запуском backend применить миграции из `backend` командой `npx prisma migrate deploy`. Миграция `20261120090000_land_listing_revisions` добавляет хранение правок. Она сохраняет существующие опубликованные объявления. Если до миграции прежняя версия была перезаписана правками, восстановить её по одному статусу или дате публикации невозможно. Миграция `20261119090000_land_listing_city` связывает старое объявление с городом при однозначном совпадении отдельной части адреса и кадастрового региона. Для остальных адресов автор может выбрать город при редактировании.

Интеграционные проверки требуют отдельную локальную БД с применёнными миграциями. `LANDS_TEST_DATABASE_URL` намеренно принимает только localhost/127.0.0.1 и точное имя базы `lands_qa`. Для тестов существующих модулей явно задавать также `DATABASE_URL`, чтобы они не использовали локальную `.env`. База должна поддерживать регистронезависимый поиск кириллицы (например, locale `en_US.UTF-8`).

```sh
# backend; обе переменные указывают на отдельные тестовые базы
npx vitest run src/lands src/chat src/services src/partners src/request-payments src/requests --testTimeout=15000 --fileParallelism=false
npm run build

# frontend
npm run test -- --testTimeout=15000
npm run lint
npm run build
```

На 17.11.2026 проверены свежая установка миграций в локальный PostgreSQL, связи и права через интеграционные тесты, HTTP-сценарий через NextAuth/BFF (публикация, файлы, приватность, избранное, карта, переписка и снятие), каталог и карта на desktop/mobile, мобильная карточка доли, создание и отправка объявления через браузер. Проверка очереди модерации выполнена через API; её визуальная проверка осталась незавершённой из-за нестабильного управления тестовым браузером. В HTTP-проверке файлов использовался адаптер хранилища в памяти: реальный S3/KMS для нового раздела требует отдельной проверки в окружении развёртывания.
