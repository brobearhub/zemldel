# Production-база данных Zemldel

Backend подключается к базе по `DATABASE_URL`. Актуальные параметры подключения и TLS берите из панели управления базой. Не сохраняйте строку подключения и пароль в репозитории или в документации. Сам факт создания кластера не подтверждает, что backend уже подключён к нему или что все данные перенесены; это нужно проверять отдельно.

## Доступ и резервные копии

- Для административного доступа используйте только разрешённый сетевой путь и проверку TLS. Если используется публичное подключение, ограничьте доступ доступными средствами.
- Проверяйте статус резервного копирования в панели управления и регулярно проверяйте восстановление.
- Бэкап справочника городов не заменяет резервную копию всей базы. Процедура импорта и merge справочника: [cities.md](cities.md).
- Репликация не заменяет резервное копирование. Число реплик и другие параметры кластера проверяйте в панели.

## Версии и инструменты

- `pg_dump` не умеет выгружать сервер более новой major-версии. Подбирайте версию клиентских утилит с учётом версии сервера и проверяйте совместимость дампов с целевой базой.

Скрипт `npm run deploy` из `backend/` выполняет генерацию Prisma Client, миграции, сиды и сборку. Он изменяет базу, указанную в `DATABASE_URL`: перед запуском убедитесь, что выбрано нужное окружение и есть актуальная резервная копия.

Для платформы с изолированной сборкой используйте `npm run tw:build` на этапе сборки и `npm run tw:start` для запуска контейнера. Сборка не обращается к базе. При старте `prisma migrate deploy` применяет только ещё не выполненные миграции; при отсутствии новых миграций сразу после проверки запускается backend. Сиды в этот процесс не входят. Ошибка миграции останавливает запуск, а не пропускается. Подробные параметры запуска и проверки состояния: [terraform.md](terraform.md#7-подключить-приложения-testing).

Статус backend, frontend, S3 и остальных компонентов проверяется отдельно: смена провайдера базы сама по себе не подтверждает их перенос.
