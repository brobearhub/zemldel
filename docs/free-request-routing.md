# Получатели свободных заявок

Свободная заявка — заявка без привязки к конкретной услуге (`serviceId = null`).
Правила распространяются на ленту, доступ к первому отклику и уведомление на вкладке.

| Категория заявки | Кто получает |
| --- | --- |
| Не указана | Все исполнители доступного региона, в том числе без опубликованных услуг |
| Общая категория | Исполнители с опубликованной услугой в этой категории или любой её подкатегории |
| Подкатегория | Исполнители с опубликованной услугой в этой подкатегории или её дочерних категориях |

Услуга в соседней подкатегории или только в родительской категории не подтверждает
узкую специализацию. Черновики услуг не учитываются.

Сохраняется действующее ограничение: регион заявки должен совпадать с регионом
города исполнителя. Для старых заявок без города используется город клиента.
Для уведомления учитывается активная организация пользователя и действующее
членство; при отсутствии активной организации применяется тот же выбор первого
членства по идентификатору, что и в авторизации.

## Защита от потока событий

- Событие создаётся после сохранения заявки; повтор идемпотентного запроса не создаёт уведомление.
- Сервер объединяет события в окна по 5 секунд, оставляя последний маркер для каждой пары «регион + категория».
- Перед рассылкой заново проверяются членство и опубликованные услуги. Каждому подключённому пользователю отправляется максимум один маркер за окно.
- Получатели читаются порциями до 500 пользователей. Содержимое и контакты заявки не передаются в уведомлении.
- При переподключении сервер возвращает последний подходящий маркер, а не последнюю заявку всего сервиса.
- Повторные и устаревшие маркеры не перезагружают список.
- На открытой вкладке новые заявки накапливаются до нажатия «Показать новые». Место под кнопку зарезервировано в заголовке, поэтому её появление не сдвигает строки.
- Фоновая синхронизация обновляет данные уже видимых строк, сохраняя их состав и порядок. При открытии вкладки и ручном обновлении применяется свежая выдача.
- Индикатор прочтения сбрасывается после успешной загрузки, только для маркера на момент её начала. Новое событие во время загрузки сохраняет кнопку и индикатор. При ошибке старый список остаётся доступным.
- Регион и категории фильтруются в БД до текущего ограничения выдачи в 200 записей.

Проверка 10 000 событий в тесте подтверждает объединение сигналов. Это не
нагрузочное испытание всей системы с 10 000 одновременных пользователей.
Существующий Socket.IO adapter работает в памяти одного процесса. При запуске
нескольких серверов нужен общий adapter, а для единого лимита рассылки между
процессами — общий агрегатор/очередь. Долговечный outbox пока не добавлен;
восстановление после разрыва соединения опирается на запрос последнего маркера в БД.

## Следующие продуктовые улучшения (пока не реализованы)

1. Отдельное отключение оповещений о заявках без категории, с сохранением доступа к ним в ленте.
2. Постраничная загрузка истории вместо одного окна из 200 записей.
3. Сводки для внешних каналов и отдельные немедленные уведомления для личных сообщений.
