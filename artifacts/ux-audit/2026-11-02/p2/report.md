# P2: актуализация заявки, финальные состояния и отзывы

Дата: 02.11.2026. Реализация и проверка в текущем рабочем дереве. Браузер: Chrome DevTools MCP, `http://localhost:4000`, три существующие изолированные сессии клиента и двух исполнителей. Новые браузерные вкладки для этой проверки не создавались.

## Реализовано

### 1. Обновление между ролями

- Общий `useVisibleRefresh`: чтение при открытии/возврате на вкладку и раз в 5 секунд на видимой странице. Карточки также реагируют на относящийся к заявке `chat.unreadHint` и восстановление socket-соединения.
- Вместе с заявкой обновляются доступные текущей стороне договоры, запрошенные документы, этапы, замечания и финансы. Смена статуса не требуется: одобрение договора, новый этап и выполнение замечания видны при прежнем статусе заявки.
- Один цикл дожидается связанных чтений; таймер не запускает параллельный цикл. Ошибка отдельного раздела сохраняет его последние данные, следующее обновление повторяет чтение.
- Локальное сохранение в workflow, договорах, финансах, этапах и кадастровых номерах приостанавливает фоновые чтения. Отменённый ответ не применяется после смены контекста или размонтирования.
- Для archived provider читается только базовая заявка; запросы договоров, этапов, финансов и замечаний сделки не запускаются.
- Отзывы обновляются отдельно и сохраняют введённые оценку и комментарий при обычном фоновом обновлении открытой формы.

### 2. Финальные состояния

- В сдаваемой/принятой/завершённой заявке без этапов нет приглашения «Добавьте первый этап выполнения работ».
- В финансовой панели `COMPLETED` показано объяснение поздней фиксации оплаты, а не инструкция пересогласовать цену. Доступные финансовые операции сохранены.
- В списке чатов у выбранного исполнителя после перехода к работам отображается актуальная стадия вместо «Договор прикреплён»/«Ожидаем договор».
- Подсказки о подготовке/согласовании договора скрыты в исполнительных и итоговых состояниях. Уведомление о прежнем локальном действии очищается, когда другая сторона меняет стадию.

### 3. Отзыв

- Начальное значение оценки — `null`, для обеих сторон.
- Пока существующие отзывы не загружены или оценка не выбрана, отправка недоступна.
- Значение проверяется как целое `1..5`; радиокнопки имеют русские доступные подписи, во время отправки оценка заблокирована.
- После публикации форма собственного отзыва исчезает; отзыв другой стороны появляется автоматически.

## Браузерная проверка

Новая SERVICE-заявка: **`b24f3807-19b7-4d5c-a416-ee172c1be8c6`**, клиент Павел Усов, исполнитель ООО «Бурый Медведь».

Начальная заявка создана через API в авторизованной браузерной сессии для подготовки тестовых данных. Тестовые PDF и подпись, ранее предоставленные пользователем, загружены через API исполнителя. Согласование цены, одобрение и подписание договора, публикация этапа, сдача, замечания, приёмка, завершение и отзывы выполнены в интерфейсе. Выбор звёзд сделан нажатием соответствующей DOM-метки MUI: сами radio-input скрыты библиотекой, поэтому прямой DevTools click по ним не срабатывал.

Дополнительно проверены существующие записи:

## Отдельные наблюдения вне этих трёх исправлений

1. **Скачивание договора возвращает 500.** На существующем SERVICE `3aa17bef…` у исполнителя GET `/api/pro/contract-files/{fileId}/download` вернул 500 и для PDF, и для подписи. После загрузки нового пакета в `b24f3807…` клиентский GET `/api/requests/{id}/contract-files/{fileId}/download` также вернул `500`, JSON `{"statusCode":500,"message":"Internal server error"}`. Загрузка пакета — `201`, список и одобрение работают. Причина сбоя скачивания не исследована; это следующая отдельная задача, мешающая прочитать договор перед согласованием.
2. При переключении desktop → mobile адаптивная оболочка пересоздала форму, и неотправленный черновик отзыва пришлось ввести заново. Сохранение при обычном polling проверено и работает; сохранение через смену брейкпоинта этим исправлением не обеспечивается.

Реальных работ и денежных переводов не выполнялось. Тестовые отзывы опубликованы в локальной среде и участвуют в её рейтингах. Новая FREEFORM-цепочка с несколькими откликами от начала до конца в этот раз не создавалась; для неё проверены существующие итоговая и архивная записи и общие компоненты.
