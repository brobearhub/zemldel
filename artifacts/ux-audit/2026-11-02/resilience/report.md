# Устойчивость соединения и повторный вход

Дата: 02.11.2026. Проверка последовательно одним агентом через Chrome DevTools MCP.

## Результат

Два дефекта восстановления чата воспроизведены на ONREZA. Исправления реализованы в dev и проверены на локальном приложении. Дополнительно проверена потеря сессии: исправлены отсутствие объяснения повторного входа, потеря несохранённого текста чата и возврат исполнителя в общий кабинет вместо исходной заявки.

Это не новая полная регрессия всех стадий SERVICE/FREEFORM. Здесь проверены восстановление открытых чатов и поведение при потере сессии на существующих завершённых тестовых заявках. Изменения ещё не развёрнуты на ONREZA.

## Изменения

- ChatSocketProvider: отложенный старт с новым токеном, обработка сетевых ошибок/5xx, повтор с задержкой 1–10 секунд, тайм-аут запроса токена 10 секунд, отмена при размонтировании, повтор при online и серверном disconnect. Авторизационные 401/403 не вызывают частые повторы. Обновление токена на здоровом соединении не пересоздаёт комнаты.
- ServiceRequestChatPanel: догрузка пропущенной истории при sync/online/focus; прерывание устаревшего запроса при смене диалога; текст состояния соединения больше не обещает обновление «по таймеру».
- ChatService.listMessages: after возвращает ближайшую следующую страницу, а не последние 50 записей после курсора; порядок `(createdAt, id)` сохраняет сообщения с одинаковым временем.
- Черновик чата хранится в sessionStorage по пользователю, заявке и диалогу; не отправляется автоматически после входа. Закрытие вкладки завершает срок жизни этого хранилища. При заблокированном хранилище редактирование работает, сохранение между переходами не гарантируется.
- Восстановление сессии использует существующее объяснение reauth; исполнитель возвращается к безопасному пути своего кабинета.

## Проверки

- Backend: 31/31 релевантных тестов (чат, доступ, замечания, сдача результата).
- Frontend: 35/35 тестов чата и live-sync; отдельно 37/37 тестов чата, черновиков и авторизации. Эти прогоны перекрываются и не суммируются.
- Детерминированная догрузка: 102 пропущенных сообщения несколькими страницами, без дублей; одинаковые timestamps; поздний ответ после переключения чата отбрасывается.
- Тесты черновиков: восстановление после remount, очистка, изоляция аккаунтов/заявок/чатов, недоступное browser storage.
- В спокойном окне 5 секунд новых API-чтений не было: счётчик 63→63. Это ограниченное наблюдение, не доказательство отсутствия любых фоновых запросов: обновление socket-токена раз в 4 минуты сохраняется.
- Полный frontend suite: **132 файла, 599/599 тестов**. После добавления ещё одного теста серверного disconnect отдельно повторён ChatSocketProvider: **5/5**.
- Production build backend и frontend прошли; TypeScript frontend проверен сборкой.
- Backend `npm run lint:check -- --quiet`, frontend `npm run lint -- --quiet`: 0 ошибок. `git diff --check` чистый.
- После сборки запущены frontend `next start -p 4000` и backend `node dist/src/main.js` (4003). Все три вкладки перезагружены на production-сборке: socket opens=1, черновики клиента и исполнителя восстановлены, архив сохранился.
- При запуске обнаружен отдельный дефект команды `backend npm run start:prod`: она ссылается на `dist/main`, а сборка создаёт `dist/src/main.js`. Код скрипта в этой задаче не менялся; локальный backend запущен по фактическому пути.
