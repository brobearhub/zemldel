# Регистрация нового клиента и восстановление пароля

Дата: 02.11.2026. Chrome DevTools MCP, текущая клиентская сессия, ширина 390 px.

## Проверено

1. Как гость создан черновик FREEFORM с задачей и Екатеринбургом; регистрация сохранила этот контекст.
2. Пустая форма показала ошибки имени, email, пароля и согласий. Фокус перешёл на имя. Несовпадение подтверждения пароля показало отдельную ошибку и перевело фокус к соответствующему полю.
3. С предоставленным пользователем адресом `photoburg@yandex.ru` зарегистрирован новый тестовый клиент «UX Тестовый клиент». Пароль сгенерирован случайно, в отчёт и репозиторий не записан.
4. Выполнен автоматический вход, без отдельного входа вручную. Сохранённая заявка опубликована автоматически и открылась её карточка. GET списка подтвердил ровно одну запись с тестовым маркером и исходный город.

Аккаунт: `3e919310-7ad4-46ea-99b3-bf0daebf706e`. Заявка: `108493e4-feb0-413c-85c6-68f37250ac41`, `NEW`.

[Новая заявка после регистрации](01-new-account-request.jpg).

## Подтверждение email

Этот шаг сейчас не реализован: signup создаёт пользователя, затем фронтенд выполняет автоматический вход. API подтверждения email и отправка подтверждающего письма в текущем сценарии отсутствуют. Предыдущее предложение включить его в проверку было неточным; новая возможность подтверждения почты в рамках теста не добавлялась.

## Восстановление пароля: проверка завершена

- Выполнен выход из нового аккаунта, открыта форма «Забыли пароль?», отправлен запрос для тестового адреса. UI показал нейтральное сообщение, не раскрывающее наличие аккаунта; горизонтального переполнения нет.
- Локально SMTP не настроен. Код использует `LogMailSender`: ссылка выводится в терминал backend, письмо в почтовый ящик не отправляется.
- Обнаружено локальное `FRONTEND_URL=http://localhost:3000` при работающем фронтенде на 4000. Значение в игнорируемом `backend/.env` исправлено на `http://localhost:4000`, backend перезапущен, HTTP 200 подтверждён, запрос восстановления выполнен повторно. Содержимое `backend/src/main.ts` после запуска watcher восстановлено без изменений.
- Пользователь предоставил свежую ссылку из терминала, уже с портом 4000. Она открыла форму смены пароля. Reset-токен в репозиторий не записывается.

[Сообщение после запроса восстановления](02-password-reset-requested.jpg).

### Результат продолжения

| Шаг | Результат |
|---|---|
| Открытие свежей ссылки | Форма «Новый пароль», два поля, горизонтального переполнения нет |
| Сохранение совпадающих новых паролей через UI | POST `/api/auth/password/reset` — `200`, переход к `/signin?notice=password-reset`, сообщение об обновлении |
| Вход старым паролем | Отказ; показано «Неверный email или пароль», сессия не создана |
| Вход новым паролем | Успешно; сессия содержит прежний ID `3e919310-7ad4-46ea-99b3-bf0daebf706e` и тестовый email |
| Контроль точных значений через API в браузере | Старые credentials — `401`, новые — `200` |
| Повторное открытие использованной ссылки и отправка той же формы | POST reset — `400`, понятное сообщение «Ссылка недействительна или устарела. Запросите новую.» |
| Возврат к заявке после входа | В профиле ровно одна заявка; открыта её карточка через ссылку списка, исходные задача и ID сохранены; GET карточки — `200` |

Обычный вход после сброса открыл главную страницу, после чего заявка была открыта из профиля; автоматический переход к конкретной заявке здесь не заявляется. В одном повторе автоматизированное заполнение дописало значение в непустой input. Этот некорректный ввод исключён из вывода о пароле: выполнены точная установка значений, успешный UI-вход и отдельная проверка старых/новых credentials. Содержимое паролей нигде не сохранено в отчёте.

## Следующий этап: локальный SMTP

После завершения описанного выше теста настроен отдельный MailCatcher для
Земледела: SMTP `127.0.0.1:1026`, интерфейс http://localhost:1081.
Backend перезапущен с локальными SMTP-переменными. Отправка формы восстановления
для тестового аккаунта создала письмо «Сброс пароля — Земледел»; оно открыто в
веб-интерфейсе MailCatcher. Ссылка ведёт на `localhost:4000`, срок в тексте —
1 час. Токен в отчёт не записывается. Внешняя доставка в Яндекс не выполняется:
письмо перехвачено локально. Настройка описана в
[docs/local-mail.md](../../../../docs/local-mail.md).
