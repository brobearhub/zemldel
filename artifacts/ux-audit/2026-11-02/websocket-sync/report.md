# Обновление заявок через WebSocket

## Изменение

Ранее `useVisibleRefresh` каждые 5 секунд перечитывал заявку и связанные
договоры, документы, этапы, замечания, отзывы и доступ чата. Таймер удалён.

После успешного изменяющего HTTP-запроса глобальный backend-interceptor
посылает `request.changed` через существующий Socket.IO gateway в личные
комнаты заказчика и активных сотрудников участвующих компаний, включая
архивных участников. Payload содержит только `requestId`. Полные данные
перечитываются через API с текущими проверками доступа.

Охвачены маршруты изменения заявки, выбора исполнителя, цены/платежей,
документов/договоров, этапов, замечаний и отзывов, а также создание диалога
и отправка сообщения. Legacy-маршруты удаления файла и ответа на отзыв
разрешают requestId отдельно. Ошибочные операции и GET не порождают событие.
Сбой уведомления не превращает уже выполненную запись в ошибочный ответ.

Frontend синхронизируется по событию соответствующей заявки, после подключения
Socket.IO, восстановления сети и возврата во вкладку. Событие во время чтения
ставит ещё одно чтение в очередь; прежние ответы отменяются при смене scope.
Для автоприёмки оставлен один timeout на конкретный `autoAcceptAt`, поскольку
backend вычисляет переход при чтении. Периодического опроса заявки нет.

## Живая проверка Chrome DevTools

Использованы три существующих изолированных контекста: клиент
`photoburg@yandex.ru`, ООО «Бурый Медведь» и ИП Медведев.
Тестовая FREEFORM: `108493e4-feb0-413c-85c6-68f37250ac41`.

- ООО предложило 12 345 ₽. Клиент получил `request.changed`, увидел цену и
  диалог без reload.
- В течение 27 секунд простоя PerformanceObserver не зарегистрировал ни одного
  API-запроса данных ни у клиента, ни у ООО (авторизационные запросы исключены).
- Второй исполнитель предложил 15 000 ₽; его отклик появился у клиента.
- Клиент выбрал ООО через UI с подтверждением. У ИП по WebSocket появился
  архивный экран и заблокировалось видимое поле чата, финансовые/workflow-блоки
  исчезли. Вкладка исполнителя не перезагружалась.
- У клиента через Chrome эмулирован Offline с сохранением viewport. ООО
  предложило 13 001 ₽. Во время Offline клиент сохранял прежнюю цену; после
  восстановления сети увидел новую. `performance.timeOrigin` до и после
  совпал: документ не перезагружался.

## Границы реализации

Событие служит сигналом перечитать API, а не передаёт документы и финансовые
данные напрямую. Первичная загрузка и синхронизация при возврате на страницу
по-прежнему создают конечную группу GET-запросов. Обновление JWT сокета раз
в 4 минуты сохранено. Проверка выполнена на одном экземпляре backend;
для нескольких экземпляров потребуется общий Socket.IO adapter.

Новых браузерных вкладок не создавалось. Реальные работы и оплаты не выполнялись.
