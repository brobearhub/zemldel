# Инструкция по дизайну и разработке сайта (Cursor Rules)

> Файл-инструкция для AI-ассистента (Cursor). Следуй этим правилам при создании структуры, вёрстки и дизайна любого сайта в этом проекте. Подход: **стратегия → структура → дизайн → запуск → развитие**.

---

## 0. Главный принцип

Дизайн подчиняется стратегии, а не наоборот. Никогда не начинай с «красивого шаблона». Сначала — цель, аудитория и путь пользователя.

Перед началом работы над любым сайтом получи (или запроси у пользователя) ответы на четыре вопроса:

1. **Какие роли есть на сайте?** (посетитель/гость, зарегистрированный пользователь, клиент, продавец, администратор, модератор, партнёр и т.д.)
2. **Для кого этот сайт?** (целевая аудитория каждой роли)
3. **Какое главное действие должна совершить каждая роль?** (у посетителя — заявка/покупка, у админа — управление контентом, у продавца — публикация товара и т.д.)
4. **Что каждой роли нужно узнать/увидеть, чтобы совершить своё действие?**

Если ответы не даны — задай эти вопросы, прежде чем писать код или предлагать дизайн. Не предполагай молча, что роль одна.

---

## 1. Этап стратегии

### 1.1 Роли
- Сначала определи и зафиксируй **все роли** на сайте (`docs/strategy.md`, раздел «Роли»).
- Для **каждой роли** пиши **отдельную стратегию** по одному шаблону:
  - **Кто это** — портрет роли, её задачи и боли.
  - **Главная цель роли** — одно ключевое действие (primary action) этой роли.
  - **Что роль должна узнать/увидеть**, чтобы совершить действие.
  - **Ключевые сценарии (user flows)** — путь роли от входа до цели.
  - **Права и ограничения** — что роль видит и может делать, а что нет.
- У каждой роли — **своя одна главная цель**; все её страницы, разделы и интерфейсы работают именно на неё.
- Публичная часть сайта строится вокруг цели основной роли (обычно посетителя); цели остальных ролей не должны конкурировать с ней на публичных страницах.
- Не добавляй страницы, блоки и функции, не работающие на цель хотя бы одной роли.

Пример структуры `docs/strategy.md`:

```
# Стратегия
## Роли
### Посетитель — цель: оставить заявку
### Клиент (личный кабинет) — цель: отслеживать заказ / повторная покупка
### Администратор — цель: быстро обновлять контент и обрабатывать заявки
```

## 2. Этап структуры (до любого дизайна)

### 2.1 Sitemap
- Составь карту сайта: список всех страниц и связей между ними, **с пометкой, каким ролям страница доступна**.
- Каждая страница должна логически вести соответствующую роль к её главной цели.
- Отдельно опиши зоны сайта: публичная часть, личный кабинет, админ-панель и т.д.
- Сохрани sitemap в `docs/sitemap.md`.

### 2.2 Wireframes
- Перед вёрсткой опиши каркас каждой страницы: порядок блоков и иерархию информации (можно текстом/ASCII в `docs/wireframes.md`).
- Делай вайрфреймы **для каждой роли и зоны** (публичные страницы, кабинет, админка) — у ролей разные задачи и разные интерфейсы.
- Никакого оформления на этом этапе: только структура, приоритеты контента и расположение ключевых действий.
- Правки вносим на этапе каркаса — это дешевле, чем переделывать готовый дизайн.

## 3. Этап дизайна

Цель дизайна — сделать информацию понятной и подтолкнуть каждую роль к её целевому действию, а не «впечатлить владельца». Единая дизайн-система (шрифты, цвета, отступы, компоненты) применяется во всех зонах сайта — публичной части, кабинете и админке.

### 3.1 Типографика
- Используй качественные шрифты (1–2 семейства максимум).
- Чёткая типографическая шкала: h1 > h2 > h3 > body, консистентные размеры и межстрочные интервалы.
- Текст должен быть читабельным: достаточный контраст, длина строки ~60–80 символов.

### 3.2 Цвет
- Ограниченная палитра: **2–3 основных цвета** + нейтральные оттенки.
- Один акцентный цвет резервируется под CTA и не используется для декора.
- Все цвета — через CSS-переменные / design tokens, без «случайных» hex-значений в коде.

### 3.3 Пространство
- Не бойся пустого пространства (whitespace) — оно делает интерфейс чище и понятнее.
- Единая шкала отступов (например, 4/8/16/24/32/48/64px).
- Не перегружай экраны: один смысловой блок = одна мысль.

### 3.4 CTA (призыв к действию)
- **Один основной CTA на роль**: в публичной части — целевое действие посетителя, повторяющееся по странице (hero, середина, футер); в кабинете и админке — главное действие соответствующей роли.
- На одном экране не размещай несколько конкурирующих кнопок разного назначения.
- Кнопка основного действия всегда визуально самая заметная на экране; второстепенные действия оформляй сдержаннее (secondary/ghost).

### 3.5 Анти-паттерны (запрещено)
- Лишние эффекты, тяжёлые анимации, параллаксы «ради красоты».
- Визуальный шум, перекрывающий главное предложение.
- Модные эффекты в ущерб удобству: ясность и юзабилити важнее визуальных трюков. Сначала — понятность, удобство пользователя и айдентика бренда, потом — эффекты.

## 4. Удобство для владельца сайта

Сайт должен быть управляемым без разработчика:

- Контент (тексты, услуги, кейсы, цены) выноси в редактируемые источники: CMS, markdown-файлы, JSON/конфиги — не хардкодь в компонентах.
- Компоненты делай переиспользуемыми и предсказуемыми: добавление новой услуги или кейса = добавление записи в данные, без правки вёрстки.
- Пиши короткую документацию для владельца: как поменять текст, добавить кейс, обновить контакты (`docs/how-to-edit.md`).

## 5. Подготовка к запуску (обязательный чек-лист)

До публикации сайта должно быть сделано:

- [ ] **SEO встроено в структуру**, а не добавлено потом: семантическая вёрстка (header/main/section/footer), уникальные title и meta description на каждую страницу, один h1 на страницу, alt у изображений, sitemap.xml, robots.txt, человекопонятные URL.
- [ ] **Аналитика настроена**: счётчик (GA4 / Яндекс.Метрика), цели на главный CTA, отслеживание источников трафика и точек выхода.
- [ ] **Несколько способов связи**: форма, телефон (кликабельный `tel:`), e-mail (`mailto:`), при необходимости мессенджеры — разным людям удобно разное.
- [ ] Адаптивность: mobile-first, проверка на основных брейкпоинтах.
- [ ] Производительность: оптимизированные изображения (WebP/AVIF, lazy loading), минимум блокирующих скриптов.
- [ ] Доступность: контраст, фокус-состояния, aria-атрибуты для интерактивных элементов.

## 6. После запуска

Запуск — это начало работы, а не её конец:

- Сайт развивается итеративно на основе данных аналитики, а не ждёт «большого редизайна» через несколько лет.
- Регулярно анализируй: откуда приходят посетители, где уходят, конвертируется ли CTA.
- Улучшения вноси небольшими проверяемыми изменениями.

## Краткая памятка (TL;DR для каждой задачи)

1. Стратегия определяет дизайн, не наоборот.
2. Сначала выясни все роли на сайте — для каждой роли своя стратегия и своя одна главная цель.
3. Сначала sitemap (с доступами по ролям) и wireframes для каждой зоны, потом дизайн.
4. Простота, ясная типографика, 2–3 цвета, много воздуха, один CTA.
5. Контент редактируется владельцем без разработчика.
6. SEO и аналитика — до запуска, развитие — после запуска.
